## Current status

Updated 2026-09-25. `MVP-Checklist.md` stays the source of truth and the dated entries at the top of `AGENTS.md` have the detail; this is the short version.

- **Released:** `codemuster@0.3.5` (tag `v0.3.5`, commit `cfb0aa9`) and the six `@codemuster/*` platform packages are on npm, published by `release.yml` through trusted publishing. `CHANGELOG.md` has every release since 0.2.8. CI runs the full suite on hosted Ubuntu, Windows, and macOS runners, and `main` requires all three. At `v0.3.5` all 1,263 .NET tests and the npm tests pass.
- **Open checklist items:** T7.6, T13.3, T13.4, T13.6 to T13.8, T13.10 to T13.12, L1 to L7 and L10 to L16, and LIVE1 (`[~]`), each with its reason in the checklist.
- **Audit loop:** `scan` maps C# with Roslyn and TypeScript with the compiler API, builds one slice per entry point plus orphan and whole-file units, and audits dependency manifests with npm, pnpm, yarn, or `dotnet list package` on every scan (D38). `run` analyzes pending units, and every finding gets a verify unit (D27, D29, D34). Non-code files are excluded from AI review, and oversized packs are skipped with a reason (D49, D50). `"exclude"` in config and `--path` scope the work. `--model` and `--effort` pass through, and the ledger records provenance (D35).
- **Fix mode:** `fix --agent <agent> [-j N]` repairs one file per worker in isolated worktrees, commits each repair that passes `test_command`, and records every finding Fixed or Declined (D37, D40, D46). It offers to stash local changes (D39), skips oversized files (D56), and drains instead of cancelling when one repair cannot be integrated (FIX2). `validate` runs the final build and test command. Fix has run with real models on this repository (the 30 `fix <path>` commits in REL032) and on ToolbagCRM.
- **Setup and agents:** `init` creates the config and installs project skills and change hooks (D42). `intelligent-config` makes one AI call to suggest exclusions, lenses, and a test command (D53). The plugin and skill follow `automation` in config (D47), the skill installs the CLI when it is missing (D44), and one marketplace plugin serves Claude and Codex (D45). `dead_code` and `user_experience` reviews are opt-in (D48).
- **Terminal:** agent commands show a banner and preview the provider, model, thinking level, and workers, with a 10 s countdown (D52, D54, D55). Run progress is colored. `status`, `doctor`, `scan`, `estimate`, `report`, and error output are still plain text.
- **Product value review (2026-09-25):** `docs/product-value-review.md` covers bugs, CLI look and feel, setup, performance, security, and features for `v0.3.5`. It lists 143 confirmed defects (11 high), 8 design questions, about 90 improvement proposals, a Top 12, and suggested releases. The raw evidence is in the ignored `TestResults/value-review-2026-09-25/`. Nothing in the review is a checklist task yet.
- **Known gaps:** see the review's Top 12. Highest: a committed `git.exe` or `node.exe` runs in place of the real tool on Windows; an untracked nested repository (such as a Claude Code worktree) makes `status`, `scan`, `fix`, and the hook exit 1; verify units are re-run when nothing changed; a failed dependency audit clears known vulnerabilities; `diff.noprefix` and similar Git settings break every fix. Also still open: inline-lambda minimal API handlers, Razor Pages, Blazor, SignalR, and gRPC are not entry points; the same defect found by two slices is reported twice (L12); gemini and opencode have never run live (T13.8); installed skill copies do not follow CLI updates (L11).
