## Current status

Updated 2026-09-13. `MVP-Checklist.md` stays the source of truth; this is the short version.

- **Phases 0 to 15 are done** except T7.6, T13.6, T13.7, T13.8, and T13.10 to T13.12, each with its reason in the checklist. Milestone B (slice mode) is reached with the fake agent and with Claude Code. `codemuster@0.1.0` and the six `@codemuster/*` platform packages are published. CI runs everything on Ubuntu, Windows, and macOS, on three self-hosted runners on Tim's R630 for the Linux leg.
- **Works today:** `scan` maps C# with Roslyn and TypeScript with the compiler API, then builds one slice per entry point (controller actions, `Map*` handlers, background services, Next.js pages) holding every function on its call path, an orphan unit for unreached functions, and whole-file units for everything else. `scan --mode file` keeps the Milestone A behavior. Every recorded finding gets a verify unit that asks a fresh call to refute it (D27, D29), and a defect in code nothing can reach is refuted (D34); `"verify": false` in config turns that off, `verify` runs only those units, and `report` leaves refuted findings out unless `--include-refuted` is given. `"exclude": ["folder/**"]` in config leaves files out of `scan` and `doctor`, and `--path <folder>` scopes `run`, `verify`, `fix`, and `estimate` to one part of a repository. `doctor` runs git and both mappers for real and prints the fix for each problem. `doctor` and `scan` print progress on stderr as they work, each line with the elapsed seconds. `--version` prints the bare version.
- **Fix mode (D37, Phase 14):** `fix --agent <agent>` plans one unit per file that has confirmed findings, runs them serially on a clean tree, and commits each file it changes. Every finding comes back Fixed or Declined with a reason, and `"test_command": ["dotnet", "test"]` in config gates each unit: a fix whose tests fail is thrown away and the file restored. Without a `test_command` it warns that nothing checks the fix.
- **Vulnerable packages (D38, Phase 15):** every `scan` audits the repository's manifests with npm, pnpm, yarn, or `dotnet list package --vulnerable`, with no agent call at all, and records each vulnerable package as an already-confirmed finding so it lands in `status`, `report`, and the fix list. `"vulnerabilities": false` in config turns it off. On ToolbagCRM it found 7 vulnerable packages across 2 manifests in about 15 s.
- **Provenance and model choice (D35):** `--model` and `--effort` pass through to each harness's own flag, and the ledger records which agent, model, and effort produced every analysis.
- **Distribution (D33):** the release workflow builds a self-contained folder build per platform as `@codemuster/<platform>-<arch>` plus the `codemuster` npm launcher, smoke-tests them through `npm install -g` on Windows, Linux, and macOS, and on a `v*` tag publishes all seven to npm through trusted publishing and attaches the tgz files to a GitHub release. `gh workflow run release.yml -f version=<x.y.z-dev.n>` builds and smoke-tests without publishing. The launcher runs the newest build it finds, updates itself in the background at most once a day (never under `CI` or `CODEMUSTER_NO_UPDATE`), and answers `codemuster update` and `update --check` itself.
- **Install it:** `npm install -g codemuster`, then in the target repository `codemuster init --yes`, `doctor`, `scan`, and either `skill install --for claude` and ask Claude Code to audit the repository, or drive it with `run --agent claude -j 4`, `report --out audit.md`, and `fix --agent claude`.
- **ToolbagCRM (Tim running it):** `doctor` mapped 15,779 C# symbols in 85 s. A scoped slice run finished 30/30 units and found 123 findings; verify by codex confirmed 114, refuted 8, and left 1 unsure. Most API endpoints are minimal API calls with inline lambdas (112 of the 137 `Map*` calls in Api and Infrastructure), which the C# entry points do not recognize, so their code lands in orphan units. Its config excludes tests, demo, the UI, mobile, edge, and `src/lib/i18n`.
- **Known gaps:** inline-lambda minimal API handlers are not entry points, which on ToolbagCRM turns most endpoint code into orphans; `fix` has never been run with a real model; the same defect found by two slices is reported and verified twice (L12); a unit that returns after its files stop being excluded is analyzed again (T13.10); a 365 KB file is still one oversized unit (T13.11); a run does not stop when the harness itself keeps failing (T13.12); `estimate` cannot count verify calls before findings exist; the `codex`, `gemini`, and `opencode` adapters have never launched their harness; entry points miss Razor Pages, Blazor, SignalR, gRPC, minimal API lambdas, and actions inherited from a base controller; the win-arm64, linux-arm64, and osx-x64 builds are built but never smoke-tested; installed skill copies do not change when the CLI updates (L11).
