# Decisions

Recorded so no session relitigates them. Add a new numbered entry to change one; never edit an
old entry in place. Dates are absolute.

| # | Date | Decision | Why |
|---|---|---|---|
| D01 | 2026-09-10 | The CLI is the outer loop; the model is the inner function called once per unit in a fresh context. | State of what has been analyzed cannot live in a context window. |
| D02 | 2026-09-10 | Language: C# on .NET 10 (current LTS). | Tim maintains it; compiles for Windows, macOS, Linux. |
| D03 | 2026-09-10 | Distribution: self-contained single-file builds per OS/arch, plus `dotnet tool install -g`. No NativeAOT. | Roslyn and MSBuildWorkspace are not AOT-friendly, and the C# mapper needs the .NET SDK on the machine anyway. |
| D04 | 2026-09-10 | Ledger is SQLite at `.codemuster/ledger.db` (gitignored). `.codemuster/config.json` (lenses, entry-point patterns, exclusions) is committed. | Simple deployment; binary DB diffs are useless in git; the Action restores the ledger from cache. |
| D05 | 2026-09-10 | Staleness key is the content hash (git blob SHA for clean tracked files, our own hash for dirty files). Modified time and size are recorded at analysis and used only as a stat cache to skip re-hashing, plus for reporting. A file modified in the same second the record was written is always rehashed next scan. | Timestamps lie on branch switch, clone, format-and-revert, and across OS clocks. Hash is truth. |
| D06 | 2026-09-10 | The ledger is unit-agnostic. Unit kinds: `file`, `slice`, `orphan`, `verify`. Every unit has members with hashes and a fingerprint. `next`, `done`, `status`, `run`, resume, and staleness never branch on kind. | File units ship first and remain the fallback and the orphan pass; slices reuse everything. |
| D07 | 2026-09-10 | A slice is one entry point plus every method on its call path, gathered at method level, not file level. A per-slice token budget degrades by distance: full bodies near the entry point, signatures plus one-line summaries for shared leaf code. The pack lists what was outlined. | Full transitive closure in a DI-heavy app is too large and mostly shared across slices. |
| D08 | 2026-09-10 | No language-server dependency and no LSP client. Batch mappers instead: Roslyn in-process for C#, the TypeScript compiler API run under `node` for TS (using the target repo's own `typescript` package), and a low-fidelity regex/import-graph fallback. multilspy is dropped. Each mapper emits the same flat code map (symbols, edges, entry points). | Language servers silently return empty results while indexing or misconfigured. Batch indexing is simpler and deterministic. |
| D09 | 2026-09-10 | Scan health gate: every mapper run records its call-site resolution rate. Below a configurable threshold scan refuses to mark slices complete and says why. `doctor` runs functional probes (load solution, resolve one known symbol), never liveness checks. Units built by the fallback mapper are marked low fidelity. | "Process is alive" was never the question. |
| D10 | 2026-09-10 | Two modes share one ledger. Interactive: the agent in the user's session runs `next`, analyzes, runs `done`. Headless: `run --agent claude\|codex\|gemini\|opencode -j N` spawns the harness per unit. In headless mode the driver is the single writer; the agent only prints JSON. Invalid JSON is recorded as a failed unit and retried, never skipped. | Interactive works on any harness; headless needs one small adapter each. |
| D11 | 2026-09-10 | Findings schema is fixed before any analysis runs: `path, line_start, line_end, severity, category, claim, evidence, confidence, lens_id`, plus a one-line `summary` of the unit in the same response. | Report, SARIF, verify, and dedupe all depend on it; changing it later strands recorded findings. |
| D12 | 2026-09-10 | A one-line summary is stored per file and per unit, paired with the hash it was generated from. | Free at analysis time; feeds slice packs, the report, and new-session orientation. |
| D13 | 2026-09-10 | Git-only for the first release. Non-git folders are on the later list. | `git ls-files` gives discovery, ignore rules, and content hashes in one process. |
| D14 | 2026-09-10 | Working name `CodeMuster` for namespaces, folders, and the `.codemuster/` directory until Tim's name research lands. Rename is a single task before first publish. | Don't block on naming. |
| D15 | 2026-09-10 | Test-driven: write the failing test first for every task, then the minimum code to pass, then refactor. Composition-root wiring is the only exemption. | Tim's explicit process choice for this project. |
| D16 | 2026-09-10 | Clean architecture, CLI flavour: `Domain` (models + interfaces, zero dependencies), `Application` (use cases, depends on Domain only), `Infrastructure` (SQLite ledger, git, file system, agent adapters, fallback mapper), `Mapping.CSharp` (Roslyn), `Mapping.TypeScript` (node runner), `Cli` (composition root, verbs, console). Tests mirror each project. | Equivalent of WebAPI / Services / Repository / Commons for a CLI. Application is testable with fakes; Infrastructure is tested against real SQLite and git in temp dirs. |
| D17 | 2026-09-10 | Code style: keep it simple; no unrequested abstractions; no comments except where logic is genuinely hard to follow; XML summaries on public Domain and Application types; nullable enabled; warnings as errors; file-scoped namespaces; records for models; no static mutable state. | Tim's stated standard. See AGENTS.md. |
| D18 | 2026-09-10 | Hand-rolled argument parsing. No command-line framework. | Eight verbs and a handful of flags. |
| D19 | 2026-09-10 | Build order: file units first (proves ledger, driver, skill, resume, incremental), then mappers and slices, then verify. A minimal verify unit ships in v0. | First dogfood output must be trustworthy or the tool loses credibility internally. |
| D20 | 2026-09-10 | Cross-platform rules: repo-relative paths always use forward slashes; processes are spawned with an argument list, never a shell string; on Windows, npm `.cmd` shims are resolved explicitly; timestamps are UTC ISO 8601; invariant culture everywhere. | Windows, macOS, and Linux are all first-class. |
| D21 | 2026-09-10 | Dogfood target: one ToolbagCRM subtree with one lens before widening. | Measure cost and finding quality before a full run. |
| D22 | 2026-09-10 | Monetization deferred by Tim ("cart before the horse"). Raise once the OSS CLI exists. | Tim's call. |
| D23 | 2026-09-10 | Final name is **CodeMuster**. Folder, namespaces, `.codemuster/` directory, dotnet tool id `CodeMuster`, npm package `codemuster` (reserved now; later an npm wrapper that downloads the platform binary so `npx codemuster` works wherever the agents are installed). Supersedes D14. | Tim chose the name; every file answers "present." |
| D24 | 2026-09-10 | First-run gate. Every verb except `init`, `doctor`, and `--help` requires `.codemuster/config.json` in the repo root; if absent it exits 2 with "not set up here; run `codemuster init`". `init` creates `.codemuster/config.json` with the default lens, and makes sure `.codemuster/ledger.db` is gitignored: on a TTY it asks before appending to `.gitignore`; with `--yes` or no TTY it appends and prints what it did; `--no-gitignore` skips. It never touches any other file. | Installed globally, the tool runs in any folder; it must refuse to invent state in a repo nobody set up, and a committed ledger is the one mistake worth preventing by default. |
| D25 | 2026-09-11 | Coverage in slice mode. Every included file belongs to at least one unit and every mapped symbol to at least one unit. `slice`: one per entry point; members are the symbols reached from it. `orphan`: one per mapped file that has symbols no slice reaches; members are those symbols, or the whole file when none of its symbols is reached. `file`: one whole file for files with no symbols, files in a language with no mapper, and files whose mapper threw (those are marked low fidelity). Supersedes the file-level orphan rule in T9.5. | A dead method in a file whose other methods are reached would never be audited under a file-level rule; the fixture's `QuoteService.ArchiveQuote` is that case. |
| D26 | 2026-09-11 | Code map contract. Symbols are code with a body: C# methods, constructors, and property or indexer accessors; TypeScript function declarations, function-valued top-level consts, and class methods. C# symbol ids are Roslyn documentation comment ids of the original definition (`M:MixedRepo.Api.Services.QuoteService.ListQuotes(System.Int32)`); TypeScript ids are `<repo path>#<name>`, `<repo path>#<Class>.<method>` for class methods, `<repo path>#default` for an anonymous default export. `signature` is the declaration without its body, whitespace collapsed, and a type member's signature starts with its type's header line (attributes, modifiers, name, base list) so class-level attributes reach the pack. `body_hash` does not change on whitespace-only or comment-only edits. Every edge points from the symbol containing a call site to a symbol with a body that the call can reach: `call` for a direct call (invocations, object creations, property and JSX element uses), `bound` for an interface member call resolved through a DI registration of that interface, `implements` for an interface member call with no DI binding (one edge per implementation), `overrides` for a virtual or abstract member call (one edge per override). Calls into code outside the map produce no edge but count as resolved. Entry point kinds are `http` (display `GET /quotes`), `background` (display is the type name), and `page` (display is the route, `/quotes`). | Slice building becomes a plain forward walk over edges, both mappers produce comparable maps, and ids stay stable so ledger members survive rescans. |
| D27 | 2026-09-11 | Verify units. `done` gives every finding it records a pending `verify` unit whose members are those of the unit that reported it, and retires the verify units of the findings it replaces; `scan` keeps a verify unit while its finding is current and that unit's fingerprint still matches the analysis, and retires it otherwise. A verify pack shows the finding and the unit's code and asks for `confirmed`, `refuted`, or `unsure` with a reason, which is stored on the finding. That pack and that response are the only places `next` and `done` look at kind; selection, fingerprints, staleness, status, resume, and `run` stay kind-agnostic, so `run` verifies every finding in the same run that recorded it. The report leaves refuted findings out and marks the rest. Refines D06. | LLM audits have a high false-positive rate (idea.md), and verified findings are what the report promises. One unit per finding keeps each check in a fresh context, and reusing the reporting unit's members means a code change invalidates the verdict with no new staleness rule. |
| D28 | 2026-09-11 | Verification can be switched off per repo with `"verify": false` in `.codemuster/config.json` (default `true`). With it off, `done` adds no verify units and `scan` retires the ones that exist; findings show as unverified. D27 and this entry wait on Tim's agreement. | D27 roughly doubles agent calls on a repo with many findings, and the first real run should not carry that cost without a way to decline it. |
| D29 | 2026-09-11 | D27 and D28 are agreed: every recorded finding is verified by default, and `"verify": false` in `.codemuster/config.json` turns it off. | Verified findings are what the report promises; T13.3 measures what verification really costs. |
| D30 | 2026-09-11 | The call graph is not stored in the ledger. `scan` rebuilds it from the mappers every time and keeps only each unit's members. Revisit after the first real-repo pass (Phase 13). | Nothing reads a stored graph yet, and storing one adds schema and staleness rules before dogfood shows a need for them. |
| D31 | 2026-09-11 | The regex and import-graph fallback mapper (D08, D09) is deferred. Files in a language with no mapper, and files whose mapper failed, stay whole-file units as D25 describes. | Whole-file units already keep coverage complete; an import graph would only add context, and dogfood will show whether that context is worth building. |
| D32 | 2026-09-11 | The skill is the main entry point. A person installs the CLI, runs `init` and `doctor`, and edits settings; their coding agent drives `scan`, the `next`/`done` loop or `run`, `status`, and `report` through the skill. The README leads with the skill. | Tim's description of the product on 2026-09-11: the AI is the driver, and people rarely trigger runs themselves. |
| D33 | 2026-09-11 | Distribution and updates. Supersedes D03's single-file builds and dotnet tool, and D23's dotnet tool id and GitHub-download wrapper. Each release builds a self-contained folder per platform (win-x64, win-arm64, osx-x64, osx-arm64, linux-x64, linux-arm64; not single-file, because Roslyn's MSBuild build host ships as folders beside the executable) and publishes each as the npm package `@codemuster/<platform>-<arch>` with `os` and `cpu` fields. The `codemuster` package is a Node launcher that lists them as optional dependencies, so npm installs only the matching build; when none is installed, the launcher downloads it on first run. The launcher keeps CodeMuster current on its own: at most once a day it asks the npm registry for the latest `codemuster` version and, when that is newer, downloads the matching platform package in the background, checks it against the registry's integrity hash, and unpacks it beside the other versions under `~/.codemuster/versions`. The next launch runs the newest version; a command already running keeps the one it started with. It never updates when `CI` or `CODEMUSTER_NO_UPDATE` is set. There is no dotnet tool. The release workflow builds the packages and attaches them to a GitHub release; Tim publishes them to npm, which needs the `@codemuster` npm organization. | The repository is private, so public users cannot download GitHub release assets, while npm serves every platform build with integrity checks and no install script. People rarely run the CLI themselves, so an update notice would go unread and updates have to happen on their own. dotnet manages tool installs itself and would fight a self-update. |
| D34 | 2026-09-11 | Verify refutes a defect in code nothing can reach. The verify pack says so: answer refuted when the repository shows nothing calls the code, and count code reached through dependency injection, reflection, routing, or a library's public API as reachable. Agreed by Tim. | The first two real runs gave opposite verdicts on `ArchiveQuote`, a stub nothing calls: one confirmed it with lower severity, the other refuted it as dead code. The report should list defects that can happen; a refuted finding is still recorded and `report --include-refuted` shows it. |
| D35 | 2026-09-12 | Provenance and pass-through model choice. `run` and `verify` take `--model` and `--effort`, passed verbatim to the harness's own flag (`claude --model X --effort Y`, `codex -m X -c model_reasoning_effort=Y`, `opencode -m X --variant Y`, `gemini -m X` with no effort support). CodeMuster keeps no list of model names or levels, so a model released tomorrow works today. Each analysis records the agent, the model, and the effort it was run with (ledger schema 4); unset means the harness's own default. Combined with `--kind`, this is how one repo gets a cheap model on orphans and an expensive one on slices. | Without provenance a mixed run gives findings nobody can attribute, and "was the cheap model good enough" stays a guess. A name list would go stale with every model release. Recording what was asked for, not what answered, is a known limit: a harness may fall back to another model. |
| D36 | 2026-09-12 | Agent pool. `--agent` repeats, each with its own slot count, model, and effort (`--agent claude:4=opus/high --agent codex:2=luna/low`). Every agent is a worker pool pulling from one shared queue, so throughput adds up and a throttled agent simply takes less work. An agent that fails (spawn failure, nonzero exit, rate limit) hands its unit back for another agent to take and goes into cooldown after repeated failures; when every agent is cooling down the run stops cleanly instead of burning attempts. An invalid response stays the unit's own problem and is retried, preferring an agent that has not seen it. `--agent <name>` alone keeps working as now. | A single provider's limit ends a multi-hour run. Two `run` processes cannot share the ledger: SQLite takes one writer and units are not leased, so pooling has to live inside one run. |
| D37 | 2026-09-12 | Fix mode. A `fix` unit holds every confirmed finding for one file plus the code the audit saw, and `codemuster fix` runs one fresh agent call per unit, so remediation has the same provable coverage as the audit (`status` reads `fix 12/48`). Each finding row records `fix_status` and a reason, the way verification does. Fix adapters run write-enabled (`claude --permission-mode acceptEdits` with edit tools, `codex -s workspace-write`, `gemini --approval-mode auto_edit`, `opencode run --agent build`); no fix adapter gets a shell, because CodeMuster runs the repository's own `test_command` itself. Rails: refuse to start with a dirty working tree; serial by default, since findings cluster in a few files; only confirmed findings; one local commit per fix unit naming the findings it addressed, never a push; a failing `test_command` counts as a failed attempt. Plain `run` never fixes: fix units are planned only by `fix`, which is the one verb that writes to the repository. | Tim: a fresh context per finding is how you know every finding was dealt with. Per file, not per finding, because a file collects related findings and two fixers in one file would clobber each other. The audit already proves the fix: changed code changes the unit fingerprint, so `scan` marks it stale and the next `run` re-audits it, and a finding that is really gone does not come back. |
| D38 | 2026-09-13 | Dependency vulnerabilities are found by the ecosystem's own tools, never by a model, and `scan` runs them every time (`"vulnerabilities": false` in config turns them off). npm, yarn, and pnpm through their `audit --json`, NuGet through `dotnet list <solution> package --vulnerable --include-transitive --format json`. Each vulnerable package becomes a finding against the manifest that declares it, category `dependency`, severity from the advisory, evidence carrying the advisory id, its URL, and the version that fixes it, recorded already confirmed with the tool named as its verifier, so it costs no agent call and lands straight in the fix list (D37). One `dependency` unit per manifest holds them, always Done, re-recorded on every scan because advisories appear without the code changing. A tool that fails or has no network leaves the previous findings alone and adds a scan warning; nothing blocks and nothing exits non-zero. | Tim: the point of the CLI is to do more with fewer tokens, so anything ordinary code can settle should never reach a model. A model asked for CVEs invents them; `npm audit` does not. Recording them as findings rather than a separate report means one inventory, one report, one fix loop. |
| D39 | 2026-09-13 | `fix` offers to stash tracked local changes before fixing confirmed findings, then restores them with their staging state afterward, including on failure or cancellation. `--stash` authorizes this without a prompt; noninteractive runs otherwise leave a dirty tree untouched. This replaces D37's unconditional dirty-tree refusal. Untracked files stay in place and outside fix commits. Restore by the exact saved stash commit, retain the recovery stash, and report its identifier if restoration conflicts. Uncommitted fix edits left by an interrupted run are saved separately before restoring the user's work; neither set of edits is discarded. | Tim: offer to stash so fixing findings can proceed without manual checkout preparation. |
| D40 | 2026-09-13 | `fix -j N` runs up to N agent calls concurrently, one file and all its confirmed findings per call. Default remains one worker. For parallel runs, each call edits an isolated Git worktree; only its assigned file's diff may be integrated. A single coordinator applies completed diffs, runs the configured tests against the accumulated fixes, commits only that file, and records the outcome. Free slots immediately take queued files. Cancellation waits for workers to stop before restoring the user's stash, retains completed commits, and leaves interrupted worker worktrees available for recovery. This replaces D37's serial-only implementation restriction. Worktree creation and removal are serialized; agent calls overlap. | Tim: 2,000 findings across 100 files should be 100 independent work units, with a configurable number running concurrently. |

Supersedes T0.1 licensing and the open-source assumption in D22 and idea.md; this is source-available. | Tim wants people to use CodeMuster without selling it.
